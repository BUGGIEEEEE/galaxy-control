# v0.5.0 — First-session paired ADB readiness

## Verdict

`PACKAGE_READY`

This release adds a bounded first-session readiness pass without turning a failed ADB recovery into
a blocker for healthy OpenMinis work:

- The first Galaxy task in a session runs the full read-only doctor; later tasks keep v0.4.0's
  selective preflight.
- `wireless-prepare --approved` first reuses one identity-verified enrolled transport.
- The executable requires a separately approved, persisted private-profile opt-in before preparation.
- When no enrolled transport exists, the fixed adapter reads `adb mdns services`, accepts exactly
  one registered-serial `_adb-tls-connect._tcp` port, and connects once to the enrolled Tailscale
  host.
- mDNS failure returns `connection_port_required`; the adapter never pairs, scans, guesses, enables
  Wireless Debugging, or falls back to fixed TCP ADB.
- Every accepted transport is checked for physical serial, model, and a canonical current boot UUID.
- Failed identity checks disconnect the newly attached endpoint, and scrcpy rereads full physical
  identity before preflight readiness or process start.
- scrcpy doctor now selects exactly one enrolled transport, checks every required safe option, and
  reports `preflight_ready` with `launch_verified: false` without starting a process.
- Doctor now reads the real OpenMinis `{ok, data, route}` response shape and requires running
  Accessibility plus running, authorized Shizuku before reporting those paths ready.
- OmO runtime metadata, autonomy boundaries, recovery guidance, and the public README describe the
  same first-session and degraded-path behavior.

## Security and compatibility boundaries

- `enable-auto-reconnect --approved` records the user's private-profile opt-in. A current
  Galaxy-control request may then perform one already-paired reconnect. New pairing remains
  separately approved and user mediated.
- mDNS is only a routing hint. Device identity is established after connection.
- mDNS may not cross Tailscale, VPN filters, routed networks, or VLANs. Manual entry of Android's
  displayed connection port remains the deterministic fallback.
- `preflight_ready` does not prove a scrcpy launch, video stream, window, or macOS Computer Use
  permission.
- This release does not change or require an upgrade to the OpenMinis Control v2 bridge runtime.
- Existing skill installations can use `install_skill.py --upgrade --approved`; activation is
  staged, the previous skill is retained as a private rollback copy, and failed activation restores
  it.
