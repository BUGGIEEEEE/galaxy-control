# v0.5.1 — Profile-selected fixed ADB final state

## Verdict

`PACKAGE_READY`

This patch restores the enrolled profile as the source of truth for ADB session completion:

- `steady_adb_enabled: true` makes the profile's Tailscale `:5555` endpoint the final ADB state.
- Official Wireless Debugging remains the bootstrapping path after a reboot, not the final endpoint
  for an opted-in fixed profile.
- The session probes an already-live fixed endpoint before dynamic recovery.
- When mDNS cannot provide a connection port, healthy OpenMinis may inspect Wi-Fi and Android's
  Wireless Debugging screen read-only. Pairing controls and the Wireless Debugging toggle remain
  untouched.
- A verified dynamic connection may run only the fixed `legacy-enable-from-wireless` profile before
  reconnecting and verifying `:5555`.
- Fixed `connect` now verifies and reports the canonical current boot-session hash in addition to
  serial and model.
- The approved installer upgrade safely migrates a user-owned real v0.4 cache parent from `0755`
  to `0700`. Symlinks, non-directories, and paths not owned by the current user fail closed.

Profiles without the fixed-path opt-in continue to use their verified dynamic Wireless Debugging
endpoint as the final ADB state.

## Safety boundaries

- Fixed TCP ADB may be reachable from the same LAN while Wi-Fi is enabled; ADB RSA authentication
  still applies.
- The persisted fixed-path opt-in authorizes only the reviewed bootstrapping and fixed-connect
  sequence during a current Galaxy-control request. It never authorizes arbitrary ADB commands,
  hosts, ports, pairing, scans, or Wireless Debugging changes.
- `preflight_ready: true` remains no-launch compatibility evidence. It does not prove a scrcpy
  process, video stream, window, or Computer Use permission.
