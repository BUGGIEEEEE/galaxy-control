# v0.5.2 — Evidence-first Shizuku port recovery

## Verdict

`PACKAGE_READY`

This patch makes the existing recovery boundaries explicit at the decision points where an agent
can otherwise take an unnecessary or invalid path:

- A fresh Shizuku launcher line that displays the Wireless ADB connection port is the first
  read-only fallback after mDNS discovery fails.
- Android's Wireless Debugging screen remains the next read-only source; the user is asked only
  when neither path can provide a current value.
- `wireless-connect` accepts exactly `--port CONNECTION_PORT` and never `--approved`.
- An already-`READY` Shizuku server is not restarted merely to redisplay a port.
- Fixed `:5555` remains the final state for an opted-in steady profile. Shizuku is not an extra
  completion condition when the requested result is only ADB or scrcpy readiness.
- A known dynamic endpoint left locally as `offline` may be removed with the existing fixed
  `wireless-disconnect --port CONNECTION_PORT` action before reconnecting and verifying fixed
  `:5555` again.
- Fixed status reports `remote_connected: true` only when the exact steady endpoint has
  `state: device`; an offline registration no longer appears connected.
- One UI launcher gestures require fresh destination evidence; a gesture that opens the
  notification shade is reversed once from a freshly observed HOME state rather than repeated.

No new bridge action, generic ADB surface, arbitrary shell, host, port scan, pairing behavior, or
OpenMinis mutation is introduced.

## Safety boundaries

- Public examples use placeholders only; no device IP, serial, live port, notification content,
  coordinate, or pairing value is retained.
- A Shizuku launcher port is accepted only from the current authorized start flow and is invalid
  after reboot or network change.
- Hidden Settings rows are never inferred from neighboring coordinates.
- Dynamic endpoint cleanup is limited to the already verified connection port.
- `preflight_ready: true` remains no-launch compatibility evidence and does not prove a scrcpy
  process, video stream, window, or Computer Use permission.
